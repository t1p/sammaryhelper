# fastgpt_exporter

Экспортёр справочника чатов, групп и каналов Telegram из архивной
PostgreSQL-базы Sammaryhelper в [FastGPT](https://github.com/labring/FastGPT)
как отдельный датасет базы знаний. Независим от `../mcp_archive_server/`
(тот отдаёт справочник как MCP-инструмент живому агенту), но переиспользует
его код подключения к БД.

**Экспортируются только метаданные** — название чата, тип (канал/группа/
личка), папка, статистика по количеству и датам сообщений. **Текст самих
сообщений никогда не отправляется в FastGPT.**

## Как это работает

При первом запуске экспортёр сам создаёт датасет в FastGPT (через API,
нужны `vectorModelId`/`agentModelId`, настроенные в вашем инстансе) и
запоминает его id в локальном файле состояния. При каждом запуске (включая
первый) он создаёт заново коллекцию с текущим снимком справочника —
предыдущая коллекция перед этим удаляется.

Почему так: у FastGPT `pushData` нет апдейта/удаления конкретного элемента
по внешнему id (ответ содержит только `insertLen`, без id вставленных
записей), поэтому точечный upsert невозможен. Справочник обычно небольшой
(десятки–сотни чатов), так что полное пересоздание коллекции на каждый
запуск — самый простой способ гарантировать, что в FastGPT ровно текущий
снимок, без накопления дублей.

**Оговорка**: путь эндпоинта удаления коллекции
(`DELETE /api/core/dataset/collection/delete`) не на 100% подтверждён для
всех версий FastGPT. Если удаление не сработает, экспортёр не упадёт —
напишет предупреждение в лог и всё равно создаст новую коллекцию и
зальёт данные. В этом случае в датасете может накопиться несколько старых
коллекций — удалите их вручную в UI FastGPT, если увидите дубли в поиске.
Сам датасет никогда не пересоздаётся.

## Настройка подключения к БД

Те же переменные, что у `../mcp_archive_server/` — см. его README:
`TG_ARCHIVE_DB_HOST/PORT/NAME/USER/PASSWORD` или `TG_ARCHIVE_DB_CONFIG_FILE`.

## Переменные окружения FastGPT

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `FASTGPT_BASE_URL` | адрес инстанса FastGPT | `http://localhost:3000` |
| `FASTGPT_API_KEY` | API-ключ | обязателен (кроме `--dry-run`) |
| `FASTGPT_VECTOR_MODEL_ID` | модель эмбеддингов (из настроек вашего FastGPT) | обязателен при создании датасета |
| `FASTGPT_AGENT_MODEL_ID` | модель-агент | опционально |
| `FASTGPT_VLM_MODEL_ID` | vision-модель | опционально |
| `FASTGPT_DATASET_NAME` | имя датасета | «Telegram — справочник чатов (Sammaryhelper)» |
| `FASTGPT_DATASET_INTRO` | описание датасета | текст про метаданные-only |
| `FASTGPT_COLLECTION_NAME` | имя коллекции | `directory` |
| `FASTGPT_PARENT_ID` | id родительской папки в FastGPT | нет |
| `FASTGPT_STATE_FILE` | путь к файлу состояния | `.fastgpt_exporter_state.json` |
| `FASTGPT_REQUEST_TIMEOUT` | таймаут HTTP-запросов, сек | `30` |
| `FASTGPT_PUSH_BATCH_SIZE` | размер пачки pushData | `200` (максимум у FastGPT) |
| `FASTGPT_DRY_RUN` | не обращаться к FastGPT | `false` |

## Установка

```bash
cd fastgpt_exporter
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

API-ключ и id моделей эмбеддингов/агента берутся в админке вашего
инстанса FastGPT (Аккаунт → API-ключи; список моделей — в системных
настройках).

## Запуск

Запускать из корня репозитория (нужен доступ к соседнему пакету
`mcp_archive_server`), как и сам `mcp_archive_server`:

```bash
python -m fastgpt_exporter.cli
python -m fastgpt_exporter.cli --dry-run
python -m fastgpt_exporter.cli --account-id +79990001122
python -m fastgpt_exporter.cli --state-file /path/to/state.json
```

`--dry-run` реально подключается к архивной БД и строит элементы (чтобы
сводка была точной), но не делает ни одного запроса к FastGPT.

## Пример содержимого одного элемента

```
Чат: "Нейрофизиология и ИИ"
Тип: группа/чат (Чат)
Telegram ID: 100
Аккаунт: +79990001122
Папка: Работа
Сообщений в архиве: 2
Период сообщений: 2026-09-15T18:31:09 — 2026-09-15T19:31:09
Обновлено в архиве: 2026-09-15T19:31:09
```

## Ограничения

- Только метаданные, без текста сообщений и без поиска по содержимому.
- Нет инкрементального апдейта отдельных чатов — каждый запуск обновляет
  весь справочник целиком.
- Максимум 200 элементов / ~10MB на один вызов `pushData` — экспортёр сам
  режет на пачки, если чатов больше.

## Файл состояния

`.fastgpt_exporter_state.json` (или путь из `FASTGPT_STATE_FILE`) хранит
`dataset_id`/`collection_id`, специфичные для вашего инстанса FastGPT —
**не коммитьте его в git** (добавьте в `.gitignore`).
